# Правила работы с проектом

## 1. Режим работы

- Проект развивается итеративно.
- LLM выступает в роли исполнителя.
- Самостоятельное расширение функциональности запрещено.
- Stack: React Native + Expo. 

---

## 2. Назначение основных файлов

| Файл | Назначение |
|------|------------|
| `specification.md` | Спецификация продукта: цели, scope, границы проекта |
| `architecture.md` | Архитектурный контракт: зоны, ответственность, технологии, стек технологий |
| `modules.md` | Перечень модулей приложения |
| `specs/*.md` | Детальные спецификации отдельных модулей |
| `project-tree.md` | Актуальная структура файлов и папок проекта |
| `implementation_plan.md` | План реализации с пошаговыми задачами |
| `project-rules.md` | Правила поведения LLM при работе с проектом |

---

## 3. Разрешённые действия

LLM может выполнять без явного запроса пользователя:

- Реализация задач из `implementation_plan.md`
- Рефакторинг внутри модуля без изменения логики
- Исправление очевидных багов в рамках существующей логики
- Декомпозиция компонентов согласно правилам (см. раздел 5)
- Добавление комментариев и документации в код
- Форматирование кода

---

## 4. Ограничения

**ЗАПРЕЩЕНО без явного запроса пользователя:**

- Изменение архитектуры
- Добавление, удаление или объединение модулей
- Изменение дизайна
- Изменение структуры проекта
- Изменение существующей логики
- Добавление новой функциональности
- Изменение публичных интерфейсов сервисов
- Изменение схемы базы данных Supabase
- Добавление новых зависимостей

Вышеперечисленные изменения возможны **ТОЛЬКО** по явному запросу пользователя.

---

## 5. Правила работы с кодом

- React-компонент, превышающий ~300–400 строк, должен быть декомпозирован на отдельные компоненты.
- Не складировать всю логику в одном файле — выносить в отдельный файл или папку.
- Бизнес-логика — только в `src/services/`.
- Компоненты не содержат бизнес-правил.
- Хуки — только координация между UI и сервисами.
- Прямые вызовы Supabase из компонентов запрещены.
- Redux — только для данных, используемых на нескольких экранах.

---

## 6. Обновление документов

- `project-tree.md` — обновлять **ТОЛЬКО** при фактическом изменении структуры проекта.
- `specs/*.md` — обновлять **ТОЛЬКО** при изменении логики соответствующего модуля.
- Документы обновляются **ТОЛЬКО** по необходимости, не при каждом действии.
- Не вносить изменения в `specification.md` и `architecture.md` без явного запроса.

---

## 7. Когда остановиться и запросить уточнение

LLM обязана остановиться и задать вопрос пользователю:

- Задача требует изменения архитектуры или структуры проекта.
- Задача неоднозначна или допускает несколько интерпретаций.
- Требуется добавление новой функциональности, не описанной в плане.
- Обнаружено противоречие между спецификацией и реализацией.
- Реализация задачи требует изменения публичного интерфейса сервиса.
- Требуется добавление новой зависимости.
- Требуется изменение схемы базы данных.
- Задача выходит за рамки текущего scope.
- Неясно, какой из нескольких подходов предпочтителен.
